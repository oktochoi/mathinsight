# UX 감사 — 2026-07-01 (v10)

이번 버전에서 두 가지 추가/수정: (1) 학부모·학생용 "일정" 화면을 단순 리스트가 아니라 공휴일 자동 표시 + 보강 일정이 보이는 **월간 캘린더**로 업그레이드. (2) AI 챗봇은 지워진 게 아니라 지금도 있음(`ParentAgentChat`) — 다만 페이지 안 별도 섹션으로 떠 있던 걸 지우고, **채팅 아이콘(FAB) 안에 "AI 도우미" 모드로 합침**. 원장용 FAB에도 "이 프로그램 어떻게 쓰는지 · 앞으로 어떻게 성장시킬지" 물어보는 AI 모드를 새로 추가.

## 열려있는 것 (재설계 필요)

### A. 학생 상세 화면 — 컴퓨터에서 오른쪽이 비어있음

`app/(app)/students/[id]/StudentDetail.tsx`가 `max-w-3xl` 단일 컬럼 — 9개 섹션이 세로로만 쌓여서 넓은 화면에서 오른쪽이 통째로 빔.

**개선 흐름**
1. 12컬럼 그리드로 전환 — 왼쪽(8컬럼)엔 기존 세로 스택 유지, 오른쪽(4컬럼)에 sticky 사이드바 신설.
2. 사이드바 내용: 학부모 연락처+대화 바로가기 / 다가오는 일정(다음 수업·예정 상담) / 최근 메모·태그 하이라이트 / 같은 반 다른 학생으로 바로 이동하는 미니 리스트.
3. 모바일에서는 사이드바 내용이 본문 아래로 자연스럽게 떨어지게(학부모 포털에 이미 있는 반응형 패턴 재사용).

### B. "[ Chart Placeholder — Billing Collection Trend ]" 문구

`components/dashboard/BillingSnapshotCard.tsx:74`, `components/billing/BillingTimelinePlaceholder.tsx:18` — 개발용 자리표시자 문구가 사용자 화면에 그대로 노출됨.

**개선 흐름**
1. 저 문구 자체를 사용자 화면에서 제거 — 개발용 placeholder와 사용자용 빈 상태(empty state)를 분리.
2. "왜 비어있고 뭘 해야 채워지는지"를 구체적으로 안내(예: "청구 내역이 3건 이상 쌓이면 여기 추이가 표시됩니다") 또는 이미 있는 "/billing" 링크로 확실히 유도.
3. 실제로 채울 계획이면 최근 N개월 수납액 막대그래프 정도로 대체.

### C. 진도(커리큘럼) — 수학 전용이 아니라 어떤 과목이든 가능해야 함

`lib/curriculumDefaults.ts`(`DEFAULT_MATH_UNITS`), `hooks/useCurriculum.ts`의 `importDefaultUnits()`가 `subject: '수학'` 고정값 — 처음부터 수학 학원 전제로 설계됨.

**개선 흐름**
1. 커리큘럼 단원 등록 시 "과목" 선택을 첫 단계로 추가.
2. 수학은 지금처럼 기본 단원 세트 제공, 다른 과목은 기본값 없이 "직접 등록"/"이전 세트 복사"로 시작.
3. 원장·강사가 "이 반이 지금 어디까지 나갔는지" 한눈에 보는 반별 진행 현황 뷰(진행바 등)를 커리큘럼 페이지에 추가.
4. 수업 마감 시점(`/lesson-logs`)에 "다음 단원으로 넘어갈까요?" 원클릭 확인을 붙여 진도 갱신 부담을 줄임.

### D. 원장 대시보드 — 배치 재검토

`DashboardActionBoard.tsx`가 `space-y-6` 단일 컬럼인데 딱 한 줄(재등록·수납 스냅샷)만 2단 — 리듬이 깨지고, 나머지 카드들은 내용물에 비해 풀와이드라 좌우 여백만 큼. 페이지 전체가 세로로 매우 김.

**개선 흐름**
1. 좌(메인=오늘 할 일) : 우(보조=현황 스냅샷, sticky) 2컬럼 구조로 재편.
2. 2단 짝짓기 기준("이번 달 스냅샷" 성격)을 다른 카드에도 일관되게 적용.
3. `DashboardMoreSection` 접이식 안 콘텐츠(운영차트·타임라인)를 오른쪽 사이드바로 옮겨 상시 노출.
4. 리스트 항목이 적을 때(오늘 수업 1~2개 등) 카드 높이를 내용에 맞게 압축.

### E. 가입은 휴대폰, 로그인은 아이디·비번 — 원장만 남음

학부모·학생은 이미 완성(`PhoneSignupWizard` → 휴대폰이 로그인 아이디, 로그인 시 인증문자 불필요). **원장(및 강사)만 이메일+비밀번호 가입**이라 통일이 안 됨.

**개선 흐름**
1. `SignupForm.tsx`에서 원장 선택 시 이메일 폼 대신 학부모·학생과 동일한 `PhoneSignupWizard`(mode `'owner'`)로 통일.
2. `LoginForm.tsx`의 "staff" 탭도 아이디 입력란을 휴대폰 번호로 통일(Google 로그인은 별도 경로로 유지).
3. 열린 질문: 강사도 같이 바꿀지(원장님 확인 필요), 기존 이메일 가입 원장 계정은 그대로 둘지(신규 가입자만 적용 추천).

### F. 원장·강사(스태프) 채팅 아이콘 — 실제 표시 여부 재확인 필요

코드상 `AppShell.tsx:84`에 스태프용 `ChatFloatingWidget`이 이미 있어서 이론상 항상 보여야 함. 실제로 안 보인다면 `profile` 로딩 지연, 다른 fixed 요소와의 충돌, `isStaffProfile` role 누락 중 하나일 가능성 — 브라우저에서 재현 확인 후 원인별로 대응.

### G. 강사별 반 할당 — 데이터는 되는데 인지 표시가 없음

`useStaffScope`가 이미 대시보드·학생목록·반목록을 담당 반으로 필터링하고, Settings에 반별 담당강사 지정 UI도 있음. 남은 건 강사 본인이 "지금 필터된 화면"이라는 걸 알 방법이 없다는 것뿐.

**개선 흐름**: 강사 로그인 시 "담당 반: A반 · B반" 배지를 사이드바/대시보드 헤더에 상시 노출. 반 미배정 강사에게는 빈 화면 대신 "담당 반이 배정되지 않았습니다" 안내. 수납·일정 화면도 같은 scope가 걸리는지 확인 후 통일.

## H. 학부모·학생 포털 — 앱처럼 "화면 자체"를 기능별로 분리 (재설계)

**바로잡음**: 이전 버전은 "한 페이지 안에서 섹션 순서만 재배치"로 잘못 정리했음. 실제 요청은 그게 아니라 — **지금처럼 한 화면에 요약·숙제·성적·출결·상담·공지·문의·수납·일정을 전부 넣고 아코디언/탭으로 접었다 펴는 구조 자체를 버리고, 앱처럼 각 기능을 완전히 독립된 화면(라우트)으로 쪼개서 "들어가야만 보이는" 구조로 바꾸는 것.**

**채팅(문의)은 예외**: 채팅은 화면 목록에 넣지 않음. 지금도 `components/chat/ParentChatFab.tsx`/`StudentChatFab.tsx`가 `ChatFloatingWidget`을 통해 화면 우하단에 **어느 화면을 보고 있든 항상 떠 있는 아이콘**으로 이미 구현돼 있음(`ParentShell.tsx`/`StudentShell.tsx` 최상위에서 렌더링). 이 부분은 지금 구조가 정확히 맞으므로 **그대로 유지** — 화면을 나누더라도 이 아이콘은 모든 화면에 공통으로 계속 떠 있게 함.

**제안하는 화면 분리안 (학부모 기준, 학생도 동일 원칙)**

```
/parent            홈 — 자녀 요약 카드 + "오늘 확인할 것"만 (진입점 역할, 상세 내용 없음)
/parent/learning   학습 — 지금의 요약·숙제·성적 3개 섹션
/parent/attendance 출결 — 지금 아코디언 안 "출결" 탭
/parent/notices    공지 — 지금 아코디언 안 "공지" 탭
/parent/payments   수납 — 지금 아코디언 안 "수납" 탭
/parent/schedule   일정 — 월간 캘린더로 업그레이드 (아래 "캘린더" 참고)
/parent/reports    상담 리포트 — 지금 아코디언 안 "상담 리포트" 탭
/parent/settings   설정 — 알림 수신 설정 + 프로필 (신설)

("문의" 탭은 아예 폐지 — 아래 참고. 채팅은 화면이 아니라 모든 화면 우하단에 상시 떠 있는 ParentChatFab 그대로)
```

**"문의" 탭은 화면으로 옮기지 않고 아예 없앰**: 코드를 다시 보니, 지금 "더 많은 정보" 아코디언 안 "문의" 탭(`InquiryTab`, `ParentPortalSecondaryPanels.tsx`)은 두 모드로 돼 있음 — "선생님께 메시지"(`ParentChatPanel`)와 "일회 문의"(`ParentMessagesPanel`). 그런데 `ParentChatPanel`을 열어보면 내부적으로 `ChatPanel`(`chat_channels` 기반 실시간 채팅)을 그대로 쓰고 있고, 이건 **상시 떠 있는 `ParentChatFab`이 여는 채팅과 정확히 같은 시스템**임. 즉 지금 "채팅"이 화면 안에 한 번(문의 탭 안), 화면 밖에 한 번(FAB) — 두 군데에 중복으로 노출돼 있었음. 학생 포털도 동일 — "선생님 · 반 톡방" 섹션(`StudentChatSection`)이 `StudentChatInbox`를 쓰는데, 이것도 `StudentChatFab`이 여는 것과 같은 컴포넌트.

그러니 "문의" 탭 자체를 화면 목록에서 완전히 제외 — 대화가 필요하면 언제 어디서든 FAB 하나로 통일. "일회 문의"(티켓형, `parent_messages` 테이블)는 실시간 채팅과 별개 시스템이긴 하지만, 사용자 입장에서 "말 걸 곳이 두 개"인 건 똑같이 혼란이므로 UI 진입점은 없애고 FAB 채팅 하나로 합침(백엔드 테이블 자체를 지울 필요는 없음, 노출만 안 하면 됨).

**"일정" 화면 — 공휴일 자동 표시 + 보강 일정 강조 (캘린더로 업그레이드)**

**검증 결과**: 지금 `/parent`, `/student`의 "일정"은 `components/portal/PortalSchedule.tsx` 하나뿐인데, 이건 **이번 주 목록**(오늘 수업 + 다가오는 8건)만 보여주는 flat list이지 달력이 아님. 공휴일 데이터를 불러오는 코드는 프로젝트 전체에서 검색해도 없음(휴일 관련 로직 자체가 없음). 즉 "공휴일이라 수업이 없다"는 걸 부모·학생이 미리 알 방법이 없고, 보강 일정도 다른 정규 수업들과 같은 형태의 리스트 항목 하나로만 섞여 있어서 눈에 띄지 않음.

**개선 흐름**
1. `PortalSchedule`을 "이번 주 리스트"에서 **월간 캘린더 뷰**로 교체 — 스태프용 `/schedule` 페이지에 이미 있는 시간대 기반 캘린더 렌더링 로직(`app/(app)/schedule/PageClient.tsx`)을 참고해 학부모·학생용으로 단순화한 버전을 만듦(학부모·학생은 편집 불가, 조회만 되면 됨).
2. 공휴일을 자동으로 불러와 달력에 표시 — 공공 API(한국천문연구원 특일 정보 API 등) 또는 오픈소스 공휴일 라이브러리를 붙여서, 학원이 따로 입력하지 않아도 달력에 "빨간 날"이 자동으로 뜨게 함. 학원 자체 휴원일(방학 등, `docs/PRODUCT_GAPS.md`에 이미 "없음"으로 기록된 항목)도 같이 표시할 자리를 만들어 둠.
3. 보강(makeup) 일정은 캘린더 셀에 별도 색상/배지로 구분 표시 — 지금처럼 다른 수업과 같은 리스트 항목으로 섞이지 않게, "이 날은 보강입니다"가 한눈에 보이게.
4. 이렇게 하면 "집에서 미리 알 수 있게"라는 목적대로, 이번 주만이 아니라 **다음 달까지 미리 넘겨보며** 보강·휴일 일정을 확인 가능해짐.

**AI 챗봇 — 없어진 게 아니라 채팅 아이콘 안으로 합침**

**검증 결과**: `components/portal/ParentAgentChat.tsx`는 지금도 그대로 있고, `/api/parent-agent`를 호출하는 AI 챗봇 맞음(사라지지 않았음). 다만 지금은 이게 페이지 안에 독립된 섹션(모바일 `#ask`, 데스크탑 `#ask-desktop` sticky 사이드바)으로 따로 떠 있어서, 위에서 "화면 자체를 기능별로 분리"하며 없애기로 한 "문의"·"톡방"과는 별개로 **세 번째 대화 창구**처럼 남아있는 상태였음. 학생 포털도 같은 컴포넌트(`ParentAgentChat`)를 그대로 재사용 중.

**개선 흐름**
1. 페이지 안의 독립 AI 섹션(`#ask`/`#ask-desktop`, 학생 쪽 "AI 학습 상담" 섹션)은 화면에서 제거 — 홈 화면을 포함한 어떤 화면에도 더 이상 이 섹션을 따로 두지 않음.
2. 대신 `ChatFloatingWidget`(FAB)을 열었을 때 상단에 **"선생님과 대화" / "AI 도우미"** 두 모드를 탭으로 넣음 — "선생님과 대화"는 지금의 `ParentChatInbox`/`StudentChatInbox`(사람과의 실시간 채팅) 그대로, "AI 도우미"는 지금의 `ParentAgentChat` 로직(질문→`/api/parent-agent`)을 그대로 옮겨서 씀. 로직 재사용이라 완전히 새로 만드는 건 아니고 "어디에 담겨있느냐"만 바뀜.
3. 부모용 AI 도우미는 지금처럼 "우리 아이 성적·숙제·학원 정보"를 물어보는 용도로 유지.
4. **원장용 FAB에는 이런 AI 모드가 지금 아예 없음**(스태프 FAB은 `StaffChatInbox` 사람 채팅만 있음) — 여기에 새로 "AI 도우미" 탭을 추가해서, 원장이 "이 프로그램 어떻게 쓰는지", "우리 학원 성장 전략은 뭐가 있는지" 같은 걸 물어볼 수 있게 함. 이건 기존 걸 옮기는 게 아니라 **새로 만들어야 하는 기능** — 학생 데이터 기반 답변(`/api/parent-agent`)과는 성격이 달라서, 제품 사용법·운영 인사이트 기반의 별도 API/지식베이스가 필요함.
5. 결과적으로 채팅 아이콘 하나를 열면 역할별로 다음이 보임: 학부모=[선생님과 대화 | AI 도우미(자녀·학원)], 학생=[선생님과 대화 | AI 도우미(학습)], 원장=[선생님·학부모와 대화 | AI 도우미(프로그램 사용법·성장 전략)].

**홈 화면(`/parent`) 설계**: 지금처럼 모든 정보를 담지 않고, "오늘 확인할 것" 카드 몇 개만 조건부로 노출 — 예: 숙제 마감 임박, 새 성적 등록됨, 안 읽은 공지 있음, 납부 기한 임박. 각 카드를 누르면 해당 전용 화면(`/parent/learning`, `/parent/notices` 등)으로 이동. 홈은 "무엇이 있는지 알려주는 진입점"이지 "내용을 다 보여주는 곳"이 아님.

**내비게이션 구조**
1. 모바일: 하단 탭바를 4~5개로 압축 — 홈 / 학습 / 출결 / 공지 / 더보기(수납·일정·상담리포트·설정을 더보기 안에 묶음). 지금 `ParentShell.tsx`의 모바일 상단 가로 스크롤 메뉴(`ParentNavLinks`, 앵커 기반)를 **실제 라우트로 이동하는 하단 탭바**로 교체.
2. PC: 이미 있는 좌측 사이드바(`ParentShell.tsx`)는 그대로 두되, 링크를 지금의 `href="#overview"` 같은 페이지 내 앵커가 아니라 `href="/parent/learning"` 같은 **실제 라우트**로 바꿈 — 메뉴 클릭 시 스크롤이 아니라 화면 자체가 전환되게.
3. 채팅 FAB(`ParentChatFab`)은 탭바·사이드바와 무관하게 `ParentShell` 최상위에 계속 유지 — 어떤 화면으로 이동해도 항상 우하단에 떠 있음(지금 구조 그대로).

**학생 포털도 동일 원칙 적용**
```
/student            홈 — 오늘 수업·숙제·새 피드백 요약만
/student/learning   학습 흐름 (요약·점수·숙제 추이)
/student/homework   숙제
/student/exams      시험·점수
/student/schedule   일정 — 학부모와 동일하게 월간 캘린더 + 공휴일·보강 표시로 업그레이드
/student/notices    공지
/student/history    수업 기록 전체
/student/settings   설정 (이미 있음 — 알림 섹션만 추가)

("선생님 · 반 톡방"도 화면 목록에서 제외 — 아래 참고. 채팅은 StudentChatFab 그대로 상시 유지)
```
**확인 결과**: 학생 쪽 현재 네비게이션(`StudentShell.tsx`)의 `{ href: '#chat', label: '톡방' }` 항목이 가리키는 "선생님 · 반 톡방" 섹션(`StudentChatSection.tsx`)을 열어보니, 내부적으로 `StudentChatInbox`를 그대로 쓰고 있음 — 이건 `StudentChatFab`(상시 채팅 아이콘)이 여는 것과 **완전히 같은 컴포넌트**. 즉 학생 포털도 학부모 포털과 똑같이, 같은 채팅을 화면 안(톡방 섹션)과 화면 밖(FAB) 두 군데에 중복 노출하고 있었음. 그러니 "톡방"을 독립 화면으로 만들 필요 없이 그냥 없애고, FAB 하나로 통일.

**정리 순서 제안**
1. 라우트부터 만들고(각 화면은 지금 있는 컴포넌트를 그대로 옮기기만 하면 됨 — 새로 만들 내용은 거의 없음), 홈 화면만 새로 설계.
2. "문의"(학부모)/"톡방"(학생) 섹션, 그리고 페이지 안 독립 AI 섹션(`#ask`/`#ask-desktop`, 학생 쪽 AI 학습 상담)은 전부 화면에서 삭제 — 채팅 FAB 하나로 흡수.
3. FAB에 "선생님과 대화"/"AI 도우미" 모드 탭 추가 — 학부모·학생은 기존 AI 로직 재사용, 원장은 신규 개발.
4. `PortalSchedule`을 월간 캘린더 + 공휴일 자동 표시 + 보강 강조로 교체.
5. 사이드바·하단탭 링크를 앵커에서 라우트로 교체.
6. 알림 설정은 새로 만드는 `/parent/settings`, 기존 `/student/settings`로 완전히 이동 — 메인 화면 어디에도 노출하지 않음.
